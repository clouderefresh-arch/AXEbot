# AXEbot

Telegram-бот персонального подбора товаров. Клиент оставляет заявку, ассистент собирает структурированный ответ с ценой в юанях, рублях и долларах.

## Стек

- Python 3.9+
- aiogram 3.x
- aiosqlite
- APScheduler
- pydantic-settings / python-dotenv

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python main.py
```

`ADMIN_ID` — Telegram ID ассистента. Клиентом может быть любой другой аккаунт. Проверка сценариев с одного аккаунта не сработает: этот пользователь всегда попадает в панель ассистента.

Черновики FSM хранятся в памяти процесса. После перезапуска незавершённый шаг сбрасывается, уже отправленные заявки остаются в SQLite (`DATABASE_PATH`).

Тесты:

```bash
pip install -r requirements-dev.txt
pytest
```

## Сценарий клиента

1. Описание текстом или фото с подписью. Кнопки шага стоят внизу экрана. Дальше фото или «Пропустить», затем срочность. Фото клиента бот не удаляет.
2. Предпросмотр. Можно поправить описание, фото и срочность, не начиная заявку заново.
3. «Дополнительные параметры»: бюджет, размер, цвет, ссылка. «-» очищает поле.
4. «Отправить заявку». Ассистент получает карточку и фото клиента.
5. «Мои заявки» — статусы и уже сохранённый ответ.
6. Пока заявка ждёт или в работе, её можно отменить (с подтверждением).
7. Когда приходит предложение, кнопки: «Принять», «Отклонить», «Уточнить».
   Принятие ставит статус `approved`, отклонение — `canceled`, вопрос уходит ассистенту без смены статуса.

## Сценарий ассистента

1. Новая заявка приходит карточкой: «Взять в работу», «Ответить», «Сменить статус».
2. «Ответить» открывает конструктор. Черновик лежит в FSM (`state.update_data`).
3. Цена вводится в юанях и сразу пересчитывается по курсу ЦБ РФ.
   Наценка применяется к юаням, затем умножается на рублёвый и долларовый курс.
4. Отдельно заполняются срок, комментарий и фото.
5. «Отправить клиенту» требует цену или комментарий. Статус становится `answered`.
   Повторная отправка помечается как обновлённое предложение.
6. Для `completed` и `canceled` ответ закрыт, пока статус не вернут вручную.
7. Списки «Открытые заявки» и «Все заявки», команда `/orders`.

Смена статуса уходит клиенту отдельным сообщением. Если клиент заблокировал бота, ассистент видит, что ответ сохранён, но не доставлен.

## Напоминания

Каждые `REMINDER_INTERVAL_MINUTES` (по умолчанию 90) ассистент получает сводку заявок в статусах `pending` и `in_progress`.

Тихие часы — с `QUIET_HOURS_START` включительно до `QUIET_HOURS_END`, не включая конец. При `22` и `9` это 22:00–09:00 в `TIMEZONE` (по умолчанию `Europe/Moscow`). В 09:00 уходит утренняя сводка, даже если интервал попал на ночь. Через 10 секунд после старта бот один раз проверяет открытые заявки и молчит, если сейчас тихие часы. Повторная сводка не уходит чаще чем раз в 30 минут.

Одинаковые границы тихих часов отключают и ночной пропуск, и утреннюю сводку.

## Доработки относительно исходного сценария

Эти шаги уже в коде. Если какой-то не нужен, его можно убрать отдельно:

- Правка описания, фото и срочности с экрана предпросмотра, отмена мастера на любом шаге.
- Очистка доп. полей символом «-».
- Решение клиента по предложению: принять / отклонить / уточнить.
- Отмена своей заявки, пока она не получила ответ.
- Уведомление клиента при смене статуса.
- Списки заявок у обеих ролей, а не только пуш новой заявки.
- Утренняя сводка после тихих часов и короткая проверка открытых заявок при старте.
- Курс юаня запрашивается у ЦБ РФ и обновляется раз в час. Числа в `.env` остаются запасными.
- Наценка отдельно от курса; в конструкторе видна и введённая сумма, и цена для клиента.
- Повторный ответ не затирается молча: клиент видит, что предложение обновлено.
- Подтверждение перед отменой заявки и перед отклонением предложения.

## Конфигурация

| Переменная | Смысл |
| --- | --- |
| `BOT_TOKEN` | Токен BotFather |
| `ADMIN_ID` | ID ассистента |
| `CNY_TO_RUB` | Запасной курс рубля за 1 юань, если ЦБ РФ не ответил |
| `CNY_TO_USD` | Запасной курс доллара за 1 юань, если ЦБ РФ не ответил |
| `MARKUP_PERCENT` | Наценка в процентах поверх курса ЦБ, `0` — без наценки |
| `TIMEZONE` | Зона тихих часов |
| `QUIET_HOURS_START` | Час начала тишины, 0–23 |
| `QUIET_HOURS_END` | Час конца тишины, этот час уже рабочий |
| `REMINDER_INTERVAL_MINUTES` | Интервал сводки |
| `DATABASE_PATH` | Файл SQLite |

Курс юаня бот запрашивает у ЦБ РФ (`https://www.cbr.ru/scripts/XML_daily.asp`) и держит его в памяти один час. Рубли берутся прямо из курса юаня, доллары — как отношение курса юаня к курсу доллара. Наценка считается поверх этого курса. Если сайт ЦБ недоступен, бот использует последний успешный курс, а при первом запуске — числа из `.env`.

Пример при курсе 12.80 ₽ и 0.14 $ за юань и наценке 15%: 100 ¥ для клиента стоят 115.00 ¥, 1 472.00 ₽ и 16.10 $.

## Структура

```text
main.py
bot/config.py
bot/database/          инициализация SQLite и CRUD
bot/handlers/client.py мастер заявки и решение по предложению
bot/handlers/admin.py  панель ассистента и конструктор ответа
bot/handlers/common.py /start, /help, /cancel, /menu
bot/services/currency.py
bot/services/scheduler.py
bot/keyboards/
bot/states/
```

Таблица `orders`: `id`, `user_id`, `user_name`, `description`, `user_photo_id`, `urgency` (`urgent` / `medium` / `low`), `status` (`pending` / `in_progress` / `answered` / `approved` / `completed` / `canceled`), `budget`, `size`, `color`, `reference_link`, `price_cny`, `price_rub`, `price_usd`, `delivery_time`, `assistant_comment`, `assistant_photo_id`, `created_at`, `updated_at`.

Команды: `/start`, `/help`, `/orders`, `/cancel`, `/menu`.
